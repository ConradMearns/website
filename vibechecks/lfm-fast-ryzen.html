Why quantization is the whole story

Multiplying weight size by generation rate gives the memory bandwidth each configuration actually achieves. Every llama.cpp build lands on the same ceiling regardless of quantization — they are all reading memory as fast as this machine physically can, so the only remaining lever is reading less of it.

What this means

  • Use Q4_K_M. It is 6.2× faster than where we started and small enough to leave most of your RAM free.
  • Parameter count is a red herring. A 2.6B model at bfloat16 reads 5.03 GiB per token — more than an 8B model at 4-bit. Bytes per token is what sets speed, not billions of parameters.
  • The runtime mattered as much as the format. At identical bfloat16 weights, llama.cpp reached 12.8 tok/s against transformers' 7.0 — same math, better kernels.
  • The iGPU is for prompts, not for typing. Vulkan gives a 5.7× prefill win but only a few tok/s on generation, because it shares the same memory.
